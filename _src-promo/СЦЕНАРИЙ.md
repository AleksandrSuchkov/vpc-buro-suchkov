# «две минуты» — финальное постановочное решение

Автоплей-ролик, презентация экспресс-диагностики воронки. 54,60 с, один HTML-файл, Motion 13 + rAF.

Каркас — из трактовки **two-minutes** (таймер как сквозной герой). Мясо — из **money-on-the-table** (холодное открытие, капли, цвет раньше цифры, ключевая фраза). Инженерия — из **product-film** (непрерывный объект, полоса прогресса, две композиции, fps-гейт). 3D-камера выброшена целиком.

**Спорные места, решённые волей режиссёра** (по одной строке на решение):

- **Верхняя рейка «предел 2:00» — снята.** Таймер, который стоит на 0:00 первые 12 секунд и потом прыгает ступенями, сам себя отличает от прогресс-бара; три подпорки под одну проблему — это признак того, что проблема выдумана.
- **Прибор в кульминации — в углу, а не на оси обмена.** impact-brand хочет прибор рядом с суммой, craft-feasibility хочет чистый раздвоенный кадр: прибор садится в левый верхний угол подписью-источником и не спорит с осью «время ↔ деньги».
- **fps-гейт оставлен, но урезан до косметики.** Он снимает тени, blur и капли — то есть украшения, одинаково на всех машинах при просадке; постановку и тайм-коды он не трогает никогда, поэтому записываемый артефакт остаётся предсказуемым.
- **Открытие — на сером, не на чёрном.** Чёрный работает как перепад яркости только если он один за весь ролик; сайт и инструмент светлые.
- **Порядок — по брифу.** Карта потерь после удара, не до: заказчик просил драматургию «результат-удар → карта потерь», а идею «сумма как вывод» мы забираем иначе — прибор и 13 полей уже показаны до неё.
- **Три починки — без выдуманных чисел.** Формулировки дословно из рекомендаций калькулятора, вместо «даёт: +33 разговора» стоит «цель по норме» из карты потерь.

## 1. Логлайн и замысел

Целевой лид на рынке подорожал вдвое, и никто не знает, во что это обходится конкретной воронке. Инструмент забирает тринадцать цифр проекта, работает одну минуту сорок одну секунду и выкладывает на чёрный экран обмен: слева «1:41 — вы потратили», справа «940 000 000 ₽ — вы теряете».

Замысел: **не пугать суммой, а показать её цену во времени.** Таймер клиента — сквозной герой: он появляется обещанием «две минуты», уходит в угол на 0:00, прыгает ступенями в такт заполнению полей, один раз за весь ролик срывается с места — в кульминационный кадр, — и возвращается в финале цифрой «1:41» со строкой «две минуты не понадобились». Обещание первой секунды закрывается на пятидесятой, с запасом.

Зритель — коммерческий директор застройщика. Он не досмотрит рекламу инструмента, но досмотрит расчёт, в котором сходится арифметика. Поэтому все цифры на экране согласованы между собой, а ролик ни разу не обещает больше, чем считает калькулятор.

## 3. Токены движения

Ложатся в один объект. Больше кривых и длительностей в ролике не заводить.

```js
const E = {
  in:   'cubic-bezier(.16, 1, .30, 1)',    // out-quart — все входы
  out:  'cubic-bezier(.50, 0, .75, 0)',    // in-quart  — все уходы
  cut:  'cubic-bezier(.83, 0, .17, 1)',    // in-out-quint — перебросы, шторки, полёты таймера
  hit:  'cubic-bezier(.19, 1, .22, 1)',    // out-expo — счётчики, удар, дуга прибора
  soft: 'cubic-bezier(.34, 1.24, .64, 1)', // единственный тычок, ровно один раз (s2, карточка «89 %»)
  lin:  'linear'                            // полоса прогресса и капли — больше нигде
};

// ровно две пружины на весь ролик, в нотации сборки (bounce/visualDuration, не stiffness/damping)
const S = {
  press: { type:'spring', bounce:.28, visualDuration:.34 }, // нажатие кнопки
  chip:  { type:'spring', bounce:.35, visualDuration:.30 }  // плашки вердиктов
};

const D = {                       // длительности, с
  flick:.12, micro:.18, tiny:.24, text:.30, lead:.36, body:.44,
  panel:.52, cut:.60, fly:.72, count:.85, gauge:1.10, big:2.20
};

const Y = { hair:6, tiny:10, text:14, card:18, drop:28, panel:38 }; // смещения, px
const X = { nudge:8, side:22, col:32 };

const ST = {                      // шаги stagger, с
  frame:.035,   // каркас 13 ячеек
  chip:.12,     // плашки вердиктов, строки «стоит:» / «цель:»
  fix:.14,      // три итога финала
  row:.16,      // резерв
  fade:.05      // групповые уходы
};

// ускорение заполнения полей: табличное, коэффициент между соседними интервалами = 0.88
const FIELD_GAP = [1.00,.88,.774,.681,.600,.528,.464,.409,.360,.316,.278,.245];
// приёмочный критерий: каждое gap[i+1]/gap[i] ≤ 0.90. проверяется одним console.table
```

**Что чем анимируется.** Motion — только `transform`, `opacity`, `filter` на элементах. Цвета, вердикты, состояния — классами (Motion ставит `fill:'both'` и навсегда перебьёт каскад). Смена цвета текста — кросс-фейдом позиционированного дубля (`position:absolute; inset:0`, тот же текст в другом цвете), а не анимацией `color`. Числа — rAF-хелпер. Полоса прогресса и капли — CSS-анимации.

## 4. Покадровый сценарий

**Общая сцена.** Логическая композиция `1200 × 675`, `transform: scale(k)`, `transform-origin: center`, `k = Math.min(vw/1240, vh/700)` считается в JS один раз при загрузке. Фон — `--gray #F0F0F0`. Фон не анимируется никогда: чёрный кадр — отдельный полноэкранный слой поверх, управляемый `opacity` и `scaleY`.

**Постоянные элементы:**

| элемент | позиция | поведение |
|---|---|---|
| таймер | x 1128, y 64 | появляется в 11.85, 34px/800, `tabular-nums`, прыгает ступенями |
| знак Бюро | x 96, y 611 | 44px, opacity .35, на чёрном кадре — белый вариант классом |
| полоса прогресса | нижняя кромка, 2px, `--blue` | одна CSS-анимация `scaleX 0→1`, 54.6 s, `linear`, `origin:left` |

Полоса прогресса — единственное, что гарантированно движется в любой паузе. Она не может рассинхрониться с таймлайном, потому что она и есть таймлайн.

**Ускорение.** Интервалы забиты таблицей `FIELD_GAP`, коэффициент 0,88 — от одного поля в секунду до четырёх с лишним. **Приёмочный критерий: ratio ≤ 0,90 для каждой пары.** Замена таблицы на ровный `stagger` обесценивает всю вторую половину ролика: пауза после нажатия стоит ровно столько, сколько было темпа до неё.

**Склейка.** Отсутствует. Карточка остаётся в кадре, в неё входит курсор. Нажатие обязано случиться там же, где заполнялись поля.

## 5. Архитектура таймлайна

### Мастер-цикл

Один `requestAnimationFrame` с абсолютными тайм-кодами и плоским списком реплик. Никаких `setTimeout`, никаких цепочек `.finished` — они накапливают дрейф и делают экранную запись невоспроизводимой.

```js
const cues = [
  { t: 0.25, fn: (i) => play(el.price, {opacity:[0,1], y:[Y.card,0], filter:['blur(8px)','blur(0px)']},
                              {duration:D.body, ease:E.in}, i) },
  { t: 1.85, fn: (i) => countTo(el.price, 12000, 24000, D.count, fmtRub, i) },
  // ...  ~140 реплик, отсортированы по t
];

let t = 0, prev = 0, paused = false, idx = 0;

function frame(now){
  const dt = (now - prev) / 1000; prev = now;
  if (!paused) {
    // ролик не «плывёт», а честно перескакивает: при просадке реплики доводятся мгновенно
    const instant = dt > 0.12;
    t += Math.min(dt, 0.12);
    while (idx < cues.length && cues[idx].t <= t) cues[idx++].fn(instant);
  }
  requestAnimationFrame(frame);
}
```

`fn(instant)` — единственный контракт: при `instant === true` реплика не анимирует, а ставит конечное состояние (`animate(..., {duration:0})` либо просто класс). Счётчики при `instant` пишут конечное значение.

**Ограничение `Math.min(dt, 0.12)`** держит t от рывка после долгого кадра; пропущенные реплики при этом всё равно доигрываются мгновенно на следующем тике.

### Пауза, вкладка в фоне, повтор

```js
const pause  = () => { paused = true;  document.getAnimations().forEach(a => a.pause()); };
const resume = () => { paused = false; prev = performance.now();
                       document.getAnimations().forEach(a => a.play()); };

document.addEventListener('visibilitychange',
  () => document.hidden ? pause() : resume());
stage.addEventListener('click', () => paused ? resume() : pause());
addEventListener('keydown', e => { if (e.code === 'Space') { e.preventDefault();
                                    paused ? resume() : pause(); } });
```

Уход вкладки в фон закрывается **паузой, а не догоном**: rAF в фоне не тикает, `t` заморожен, ни одна реплика не пропущена. `prev` обязательно переставляется при возврате — иначе первый кадр после фокуса даст гигантский `dt`.

**Повтор:**

```js
function restart(){
  document.getAnimations().forEach(a => a.cancel());   // Motion ставит fill:'both' —
  stage.className = baseClasses;                        // без cancel второй прогон
  resetInlineStyles();                                  // стартует с конечных состояний первого
  void stage.offsetWidth;                               // рестарт CSS-анимаций (полоса, капли)
  t = 0; idx = 0; prev = performance.now(); paused = false;
}
```

### Числа

Один хелпер на весь ролик — mini-`animate` числа не умеет:

```js
function countTo(el, from, to, sec, fmt, instant){
  if (instant) { el.textContent = fmt(to); return; }
  const t0 = performance.now(), ms = sec * 1000;
  (function step(now){
    const k = Math.min(1, (now - t0) / ms);
    el.textContent = fmt(from + (to - from) * (1 - Math.pow(1 - k, 3))); // easeOutCubic
    if (k < 1) requestAnimationFrame(step);
  })(t0);
}
```

Тот же хелпер гонит дугу прибора: пишет `el.style.setProperty('--p', deg + 'deg')`, а `conic-gradient` читает переменную. Ничего переизобретать не нужно — это тот же механизм, что `setGauge` на странице калькулятора.

Все крупные числа — `font-variant-numeric: tabular-nums`, иначе строка дышит и на записи это видно.

### Разделение обязанностей

| что | чем |
|---|---|
| transform / opacity / filter на элементах | Motion `animate` |
| групповые входы и уходы | Motion `stagger` |
| цвета, вердикты, состояния прибора, кегли после приземления | **классы**, никогда не Motion |
| смена цвета текста | кросс-фейд позиционированного дубля (`inset:0`, тот же текст) |
| полоса прогресса | одна CSS-анимация `scaleX` на 54.6 s, `linear` |
| капли утечки | CSS `@keyframes`, `infinite`, разные `animation-delay`, 5 узлов |
| счётчики и дуга | rAF-хелпер |

**Дисциплина `will-change`.** Вешается классом на входе в тяжёлую сцену (s4 — карточка с 13 полями, s8 — карта с каплями) и **снимается на выходе**. Постоянный `will-change` на сорока узлах съедает кадр сам по себе, без всякой анимации.

### fps-гейт

Замер средней длительности кадра по rAF за первые 2 секунды. Ниже 50 fps → класс `.lite` на `#stage`:

- `box-shadow` карточек → хайрлайн 1px,
- `filter: blur()` на входах → просто `opacity`,
- капли → статичные коралловые точки у пяти строк.

**Ни один тайм-код, ни одна задержка, ни одна реплика не меняются.** Гейт трогает только украшения, поэтому записываемый артефакт остаётся одинаковым на любой машине.

## 6. Мобильная версия

**Вторая композиция, а не адаптив.** При загрузке выбирается одна из двух логических сцен и не меняется посреди ролика:

- ландшафт `1200 × 675` (по умолчанию),
- портрет `720 × 1280` при `matchMedia('(max-width: 780px)')`.

**Таймлайн, тексты, задержки, stagger — общие. Ветвятся только сетки и кегли**, они лежат в одной карте `{ desktop, portrait }`.

| сцена | что перестраивается |
|---|---|
| s1, s3, s10 | кегли −25 %, переносы строк по-другому. Больше ничего |
| s2 | три карточки уже стоят колонкой — портрет меняет только ширину |
| **s4** | сетка 3×5 → **2 колонки × 7 рядов, все тринадцать полей на месте.** Кнопка занимает 14-ю ячейку. Иерархия держится размером (28px герои против 19px), не кадрированием — прятать поля нельзя, весь смысл кадра в том, что цифр тринадцать и они конкретные |
| s5 | курсор входит снизу, а не справа |
| s6 | прибор Ø 200px |
| **s7** | ось обмена поворачивается на 90°: «1:41 / вы потратили» сверху, хайрлайн горизонтальный, «940 000 000 ₽ / вы теряете» снизу. Число — `clamp(56px, 13vw, 140px)`, разряды переносить нельзя, поэтому кегль считается от ширины |
| s8 | колонка итогов уезжает из-под правого края **под карту** отдельной строкой в три колонки; норма прячется под значение вторым уровнем строки; высота строки 62px |
| s9 | три карточки колонкой, «стоит:» и «цель:» в одну строку |
| s11 | всё уже колонкой, кнопка на всю ширину минус поля |

Таймер в портрете стоит в правом верхнем углу той же логической сцены — позиции считаются от размеров композиции, не от вьюпорта.

## 7. prefers-reduced-motion

Не «ролик без анимаций», а **другой носитель**: девять статичных кадров в конечных состояниях с ручным перелистыванием. Автоплей выключен, полоса прогресса заменена счётчиком «3 / 9».

| # | кадр | таймер | состояние |
|---|---|---|---|
| 1 | цена входа | — | «24 000 ₽ ×2», подпись «сейчас», число коралловое |
| 2 | рынок 2026 | — | три карточки, шкала к3 отрисована |
| 3 | две минуты | 0:00 | обе подписи, таймер уже в углу |
| 4 | тринадцать цифр | 1:38 | все 13 полей заполнены, подпись «всё остальное считает сам» |
| 5 | прибор | 1:41 | дуга на 180°, «50», «сильная воронка — от 70» |
| 6 | **обмен** | 1:41 | чёрный кадр целиком собран: таймер слева, сумма справа, хайрлайн, строка-источник |
| 7 | карта потерь | 1:41 | 8 строк, все вердикты, 5 планок, капли — статичные метки, колонка итогов |
| 8 | три починки | 1:41 | все три карточки со «стоит:» и «цель:» |
| 9 | финал | 1:41 | «две минуты не понадобились», три итога, кнопка, ссылка, знак |

Листание — стрелки ←/→, пробел, тап по правой половине кадра, точки навигации снизу. Ни одного `transform` с ненулевой длительностью. Кадры собираются той же вёрсткой с классом `.frame--static` — отдельной разметки нет.

**Побочная выгода:** эти девять кадров бесплатно становятся постерами под соцсети и презентацию — снимаются скриншотом, без отдельной работы.

## 8. Управление

По умолчанию — просто играет. Зритель видит:

| элемент | когда | поведение |
|---|---|---|
| полоса прогресса, 2px, `--blue`, нижняя кромка | всегда | `scaleX 0→1`, 54,6 с, `linear`. Показывает остаток и в любой паузе доказывает, что кадр идёт |
| пауза | клик по кадру, пробел | замораживает `t` + `document.getAnimations().pause()`. Индикатор — та же полоса, она встаёт |
| авто-пауза | уход вкладки в фон | `visibilitychange`, возврат — авто-resume |
| «смотреть заново» | с 54.20, opacity .50, левый низ | `restart()` — полный `cancel()` всех анимаций и сброс |
| кнопка «пройти диагностику» | с 51.90, кликабельна с 52.40 | настоящая ссылка, остаётся на стоп-кадре сколько угодно |

Ничего больше на экран не выводится: ни таймлайна с ползунком, ни кнопок скипа. Это кино, а не плеер.

## 9. Карта рисков — что проверять в первую очередь

**1. Ускорение 13 полей выродилось в ровный stagger.** Первое, что ломают при вёрстке. Пауза после нажатия работает только потому, что перед ней темп дошёл до четырёх событий в секунду; на ровном ритме те же 1,2 с прочитаются как зависание, и вся вторая половина ролика перестанет окупаться.
**Проверка:** `console.table` интервалов и отношений соседних. **Приёмочный критерий: каждое ratio ≤ 0,90.** Это не пожелание, это условие приёмки.

**2. Пауза 1,20 с после нажатия и 2,20 с в кульминации читаются как поломка.** Автоплей без звука, зритель не нажимал play.
**Проверка:** смотреть на записи, не в живом браузере, и с чужого экрана. Страховка уже встроена: полоса прогресса идёт всегда, таймер «1:41» стоит в углу, в кульминационной тишине на 33.60 проявляется строка-источник, а в паузе карты потерь продолжают падать капли. Если пауза всё же не сработала — сокращать, но не ниже 0,95 с и 2,00 с соответственно.

**3. Крупный текст мылит из-за масштабирования слоя.** Три места: таймер в кульминации (2,4×), таймер в финале (2,4×), карточка на входе (1,06×).
**Проверка:** стоп-кадр записи на 33.00 и на 53.00, смотреть на «1:41». Лечится приземлением: на кадре окончания полёта transform снимается и кегль ставится классом. Если в записи всё ещё мягко — снизить множитель до 2,0 и добить кеглем базового состояния.

**4. Сцена s8 роняет кадры.** Самая тяжёлая: 8 строк + 8 плашек + 5 планок + 5 бесконечных капель + тени карточек.
**Проверка:** записать s8 на самой слабой доступной машине. Порядок отключения при провале — сначала тени (класс `.lite`), потом капли до трёх, планки и плашки не трогать: это смысл сцены.

**5. Второй прогон стартует с конечных состояний первого.** Классика `fill:'both'`.
**Проверка:** нажать «смотреть заново» и убедиться, что s1 играет от нуля, а не с готового «24 000 ₽». Лечение — `cancel()` по всем анимациям плюс `void offsetWidth` для рестарта CSS-анимаций полосы и капель.

**6. Арифметика на экране.** Комдир проверяет на слух: 595/1860 = 32 %, 280/595 = 47 %, 31/595 = 5,2 %, 12 400 000/595 = 20 840 ≈ 20 800 ₽.
**Проверка:** сверить все значения s4 против всех значений s8 перед сдачей. Если меняется хоть одно входное число — пересчитать всю карту потерь; выборочная правка ломает согласованность, а её ловят.

**7. Ролик обещает больше, чем считает инструмент.** Формулировки s9 обязаны совпадать с массивом рекомендаций калькулятора дословно, а «цель:» — с нормой соответствующей стадии.
**Проверка:** открыть `leads/diagnostika`, прогнать на тех же 13 цифрах, сверить три рекомендации построчно. Ролик и инструмент должны говорить одинаково.

**8. Мобильная композиция переключилась посреди прогона.** Поворот телефона или смена размера окна не должны менять сцену.
**Проверка:** повернуть телефон на 20-й секунде. Композиция выбирается один раз при загрузке; при `resize` пересчитывается только коэффициент `k`, но не раскладка и не тайминги.
